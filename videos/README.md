# Video and Learning Resource Catalog

This directory contains the chapter-aligned resource lists for Parts 1–10. The historical filenames still contain `YoutubeVideos` for compatibility, but the catalog now includes official documentation, courses, conference presentations, and other learning resources when a verified video could not be identified.

A link in a Part file means that a target is assigned. It does **not** by itself mean that the displayed title, duration, provider, and chapter scope have all been independently verified. Entries without a link are discovery candidates, not recommendations ready for publication.

## Source of truth and generated files

The authored `Part_*_YoutubeVideos.md` files and the manually maintained `video_resource_status.csv` file are the source of truth. The remaining catalog files are generated by `validate_video_resources.py`:

- `video_catalog.csv` and `video_catalog.json`: one normalized record per resource entry.
- `video_review_queue.csv`: the 15 linked-but-unverified entries followed by the 189 unlinked discovery candidates.
- `unlinked_resource_candidates.csv`: unlinked entries, including exact-title clues from elsewhere in the subtree.
- `duplicate_targets.csv`: targets reused in more than one entry, with titles and chapters for scope review.
- `video_summary.json`: aggregate counts by part, target type, and host.

Generated files should not be edited by hand.

## Status meanings

`resolved_official_replacement` identifies an entry whose demonstrably wrong or contradictory target was replaced with a primary, official resource.

`verified` identifies an assigned link whose displayed identity and subject were corroborated by a primary record, the publisher, the author, or a sufficiently specific indexed source that preserves the exact target.

`review_required` identifies an assigned link for which reliable current or archived metadata could not be recovered. The registry records a plausible primary-source fallback, but that fallback is not automatically substituted when it is not demonstrably the intended video.

`assigned` is the default for a linked entry that has no fourth-pass exception record. It should not be read as a guarantee of continuing availability or perfect metadata.

`unlinked_discovery_candidate` identifies a heading that currently has no URL.

## Validation and regeneration

From the repository root, regenerate the derived catalog with:

```bash
make video-catalog
```

The command checks the ten expected Part files, table-of-contents anchors, Markdown URL-label/href agreement, URL structure, YouTube ID structure, placeholder text, duplicate resource identities, canonical YouTube formatting, and consistency with the manual status registry. It then regenerates the catalog and review files. `make validate` independently rebuilds those generated files in a temporary directory and fails if committed outputs have drifted.

A normal run succeeds with aggregate warnings for known editorial backlog. To make warnings fail a CI job, use:

```bash
python3 videos/validate_video_resources.py --write --strict
```

The validator uses only the Python standard library and does not make network requests. Remote availability and metadata should be rechecked periodically with an approved external-link process; automated `HEAD` requests alone are not reliable for YouTube and many documentation platforms.

## Editorial policy

1. Prefer the original publisher, project, standards body, research group, or official documentation over reposts and aggregators.
2. Do not replace a dead or unverified video solely because another resource has a similar title.
3. Preserve meaningful YouTube playlist and timestamp parameters while normalizing hosts and video paths.
4. Record every exceptional replacement or unresolved linked target in `video_resource_status.csv` with the review date, evidence, and recommended action.
5. When the chapter intent is ambiguous, keep the item in the review queue rather than presenting a plausible guess as verified.
