Agent Service API

InterfaceTools & IntegrationOrchestration & ToolsVariation point (abstract)arc:AgentServiceAPI

A network API through which an agent exposes its capabilities as a distributed service to agents across platform, language or organisational boundaries.

Responsibility. Exposes an agent's capabilities as a remotely callable service.

Also known as: Agent API, Inter-domain API

Variants

VariantWhen to choose
REST Agent APIChoose when human readability matters, clients are diverse (any HTTP client), performance requirements are moderate, and REST infrastructure can be reused.
gRPC Agent APIChoose when throughput and latency are critical, type safety matters, bidirectional streaming is needed, and both client and server implementations are controlled.

Design guidance

  • SHOULD be chosen when agents span networks or organisational boundaries or contract-first development is needed.
  • MUST return specific status codes (e.g., 429, 503, 400, 409) with structured error bodies so callers can choose retry, escalation or correction.
  • SHOULD NOT hold synchronous connections for long-running operations; return a job ID, use webhooks or server-sent events.
  • SHOULD use connection pooling to avoid SNAT port exhaustion under rapid calls.
  • SHOULD support client caching of unchanging data with explicit invalidation.

Quantitative guidance

As stated by the sources; verify before use.

  • SNAT ports are reclaimed only 4+ minutes after connection close, causing sporadic HTTP 500 errors (Ch1.3).
