Optimistic Lock Controller

Software componentOrchestrationOrchestration & Toolsarc:OptimisticLockController

A state concurrency controller in which instances detect update conflicts at write time and retry.

Responsibility. Detects conflicting state writes and retries them.

Also known as: Optimistic locking

Variant of State Concurrency Controller abstract

When to choose. Choose when instances can detect conflicting updates and retry them.

Design guidance

  • SHOULD re-read state, merge and retry with exponential backoff on version conflict rather than fail the write.
  • SHOULD be preferred when conflicts are rare, since agents work in parallel and serialise only at mutation.

Quantitative guidance

As stated by the sources; verify before use.

  • State-consistency failures reduced 88%; 76% of conflicts resolve on first retry, 18% on second, 6% need a third retry or manual intervention; Writer-Reviewer pair caused 62% of conflicts (Ch8.2A).
