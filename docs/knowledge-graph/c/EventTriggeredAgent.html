Event-Triggered Agent

Software componentOrchestrationOrchestration & Toolsarc:EventTriggeredAgent

A stateless agent function that stays dormant until a subscribed event arrives, reconstructs context from the event payload and external stores, acts, and emits result events for downstream agents.

Responsibility. Performs one specialised agent step in response to a subscribed event type.

Also known as: Serverless agent, Agent function, Event-driven agent

Design guidance

  • MUST obtain all required context from the triggering event or external storage, never from in-memory state persisted between invocations.
  • MUST process events idempotently by recording processed event IDs, because delivery is at-least-once.
  • SHOULD place expensive initialisation (model loading, database connections, configuration) outside the per-request handler so warm invocations reuse it.
  • SHOULD be invoked asynchronously rather than synchronously from the API gateway, and SHOULD NOT turn naturally synchronous queries into events.
  • SHOULD save progress to durable storage and exit gracefully before the platform timeout for long-running workflows.

Quantitative guidance

As stated by the sources; verify before use.

  • Lazy-loading a 2 GB model keeps cold starts under 1 s versus 30+ s when loaded on every cold start (Ch4.2).
