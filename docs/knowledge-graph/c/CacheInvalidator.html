Cache Invalidator

Software componentModel ServingModelsarc:CacheInvalidator

A component that removes specific cache entries when underlying data changes, driven by database triggers, broadcast events, webhooks or operator commands.

Responsibility. Removes stale cache entries when source data changes.

Also known as: Event-driven invalidation, Cache admin purge, Dependency-aware invalidator, Event-based cache invalidation, invalidate_pattern

Design guidance

  • SHOULD map source-data changes to affected cache keys for fine-grained invalidation where hit rate matters.
  • SHOULD provide operators manual purge as a last resort when automated invalidation fails.
  • MUST treat write-invalidation failures as correctness bugs, invalidating affected entries atomically with the source write.
  • SHOULD combine event-driven invalidation with a TTL bound so staleness stays bounded even when invalidation fails.
  • SHOULD account for writers outside the application (manual edits, batch ETL, third parties) via CDC streams or conservative TTLs, since cache-aside assumes a single coordinated writer.
  • SHOULD invalidate related cached queries, contexts and responses when documents are added, modified or deleted.
