Sliding-Window History Truncator

Software componentMemoryCognition & Memoryarc:SlidingWindowHistoryTruncator

A context window manager that retains only the most recent N items of a history field, discarding older ones.

Responsibility. Keeps only the last N history items in state.

Also known as: keep_last_n operator, Maximum history limit, ConversationBufferWindowMemory, Blind context truncation, Truncation, Rolling buffer

Variant of Context Window Manager abstract

When to choose. Choose as the simplest bound when losing early conversation detail is acceptable.

Design guidance

  • SHOULD be expressed as a reducer on the state schema so pruning happens automatically on every update.
  • SHOULD NOT be used where early turns establish account details, preferences or constraints that later turns depend on.

Quantitative guidance

As stated by the sources; verify before use.

  • Example bound: keep only the last 15 conversation turns (Ch1.6).
  • Truncation saving ~20% of token cost often increases hallucination rates by 50%+ (Ch3.10).
  • Truncating the oldest conversation turns saves ~20-40% of tokens (Ch5.9).
