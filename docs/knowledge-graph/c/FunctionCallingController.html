Function-Calling Controller

Software componentOrchestrationOrchestration & Toolsarc:FunctionCallingController

An agent controller that presents all registered function specifications to an LLM and lets model-native function calling choose, parameterize, order or parallelize function invocations, adapting to returned results.

Responsibility. Routes each request dynamically to registered functions using LLM function-calling decisions.

Also known as: Kernel orchestrator, Orchestrator LLM, Dynamic plugin router, Function-calling planner, Auto function invocation

Variant of Agent Controller abstract

When to choose. Choose when an agent must integrate an extensive, growing catalog of capabilities (tens of functions across many domains) whose composition cannot be pre-programmed and new capabilities must be added without changing orchestration code. Avoid for focused agents with fewer than five capabilities, or for workflows needing iterative refinement loops, conditional branching on intermediate results, or strictly deterministic execution (prefer explicit state-graph orchestration).

Design guidance

  • SHOULD incorporate newly registered functions into routing without changes to orchestration code.
  • MUST NOT be relied on for deterministic execution sequences; routing is non-deterministic even at temperature 0, so compliance-critical steps need constrained function-choice behaviour.
  • SHOULD serve as the single mediation point where monitoring, token accounting and audit of executed capabilities are injected uniformly.

Quantitative guidance

As stated by the sources; verify before use.

  • Plugin routing is described as scaling from about 5 to 50 capabilities (10 to 50 functions) without proportional orchestration complexity (Ch2.5).
  • Routing identical queries can differ across executions even at temperature=0 (Ch2.5).
