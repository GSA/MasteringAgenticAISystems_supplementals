Retrieval Result Cache

Data storeKnowledge & DataKnowledge & Dataarc:RetrievalResultCache

A cache of previously retrieved documents and context, reused to cut retrieval latency for repeated queries and to continue service when live retrieval fails.

Responsibility. Serves cached documents when retrieval is unavailable.

Also known as: Cached documents, Cached retrieval fallback, Top-K query result cache, Hot chunk cache, Retrieved context cache, Context cache

Design guidance

  • SHOULD serve as fallback when retrieval fails rather than erroring.
  • SHOULD key entries on query embedding plus retrieval parameters (top-K, filters).
  • SHOULD apply TTLs matched to knowledge base update frequency to bound staleness.

Quantitative guidance

As stated by the sources; verify before use.

  • Saves 100-300 ms retrieval latency per hit; retrieval-layer cache hit rates often exceed 40% (Ch6.5).
