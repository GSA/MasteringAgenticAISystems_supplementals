Risk Gate

Software componentHuman OversightExperience & Human Oversightarc:RiskGate

An oversight gate that scores proposed actions on impact factors such as financial amount, data deletion, external API calls, and customer reach, escalating by cumulative risk score.

Responsibility. Escalates actions whose assessed risk exceeds policy thresholds.

Also known as: Risk-based gate, Risk assessment, Risk-based oversight selector, High-stakes decision gate, Mandatory human checkpoint, Tiered oversight, Autonomy gradient, Materiality threshold routing

Variant of Oversight Gate abstract

When to choose. Choose when escalation must reflect action impact (financial amount, deletion, external calls, customer reach) regardless of agent confidence.

Design guidance

  • SHOULD implement organisational risk policies as explicit, auditable scoring rules.
  • SHOULD select oversight intensity from action reversibility, error consequence severity and operational scale.
  • SHOULD weigh financial impact, reversibility, stakeholder sensitivity and uncertainty when setting authority for a decision.
  • SHOULD escalate decisions in regulated or safety-critical domains (e.g., medical supply procurement) to humans regardless of confidence.

Quantitative guidance

As stated by the sources; verify before use.

  • Example scoring: >$10,000 = 3 pts, any deletion = 5, external API call = 2; >=5 requires approval, 3-4 shows risk details, <3 proceeds (Ch1.1A).
  • Code example: >$10k = 5, deletion = 5, external API = 3, >500 recipients = 4; >=5 approval, >=8 monitoring dashboard (Ch1.1B).
  • Layered production example: HITL for ~1% of actions, HOTL for ~10%, HOVL for ~89% (Ch9.2).
  • Prudential: 60% of claims process automatically, 40% escalate to human reviewers; $12M annual savings with 100% regulatory compliance (Ch10.1).
  • Reference thresholds: financial amounts over $10k, and any privacy, safety or regulatory impact, count toward the risk score; score > 2 escalates (Ref10.01).
