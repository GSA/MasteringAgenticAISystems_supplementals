Tool Registry

Data storeTools & IntegrationOrchestration & Toolsarc:ToolRegistry

A structured inventory of available tools holding each tool's name, description, input/output schemas, and execution context such as permissions, rate limits, and invocation constraints.

Responsibility. Catalogues tool metadata for selection and invocation.

Design guidance

  • SHOULD expose each agent to a focused toolset rather than an extensive library.
  • MUST use clear, descriptive tool names and descriptions.
  • SHOULD group related functions into capability-domain plugins registered as units.
  • SHOULD allow the same plugin to be registered with multiple agents so capability integrations are reused rather than rewritten.
  • SHOULD organize related tools into logical groups with explicit distinctions between similar tools.
  • SHOULD retire tools whose removal causes minimal degradation in ablation because other capabilities (e.g., code execution) cover their tasks.
  • MAY package related functions together as function groups for simplified tool management.
  • SHOULD describe each tool's parameters, side effects and reversibility so the policy engine can use them in policy evaluation.

Quantitative guidance

As stated by the sources; verify before use.

  • Agents with focused toolsets of 5-8 tools outperform generalists with 30+ tools; evaluating 20+ tools per decision degrades reasoning (Ch1.2).
  • With 20+ tools in a single flat agent tool list, LLM tool selection becomes unreliable (Ch2.5).
