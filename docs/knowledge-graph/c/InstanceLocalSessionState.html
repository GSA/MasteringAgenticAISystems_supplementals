Instance-Local Session State

Data storeMemoryCognition & Memoryarc:InstanceLocalSessionState

Session state held in a replica's own memory, requiring session affinity so a user's requests return to the same replica.

Responsibility. Keeps a user's session state in the serving replica's memory.

Also known as: Local memory state store, Sticky-session state, LocalMemory, Local TTL context cache

Variant of Conversation State Store abstract

When to choose. Choose when latency requirements are extreme (sub-100 ms), scale is modest (tens of instances), and session recreation after instance failure is acceptable.

Design guidance

  • SHOULD NOT be used where autoscaling or instance failure would lose sessions unacceptably; new instances receive no traffic until sessions form.
  • SHOULD be limited to short-TTL caching with invalidation logic in hybrid designs; relying on it forces session affinity and loses context on replica failure or rolling update.

As stated by the sources; verify before use.
