Service Container

Software componentTools & IntegrationOrchestration & Toolsarc:ServiceContainer

A dependency-injection container that registers shared services (AI model services, database connections, HTTP clients) and injects them into capability functions under central configuration.

Responsibility. Supplies centrally configured shared dependencies to capability functions through injection.

Also known as: Kernel, Dependency injection container, Service registration

Design guidance

  • SHOULD provide database connections, API clients and model services as injected dependencies rather than letting each function create its own.
  • SHOULD keep credentials and connection strings in central configuration to simplify rotation and security auditing.
  • SHOULD pool connections at the container rather than per plugin to prevent resource exhaustion under concurrency.
  • SHOULD enable testing by allowing injected dependencies to be replaced with mocks.
