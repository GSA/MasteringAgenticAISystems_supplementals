Rate Limiter

Software componentSafety & SecuritySafety, Security & Governancearc:RateLimiter

A control that caps the rate of agent tool invocations to protect downstream systems from overload by runaway agents.

Responsibility. Caps agent request rates to protected tools.

Also known as: Rate limiting, Throttler, Application-level rate limiting, Gateway rate-limiting plugin, Gateway rate limiting, Ingress rate limiting, API request throttler, API rate limiting, Inference API rate limiting, Token bucket rate limiter, Resource constraint layer, Approval request rate limit

Design guidance

  • SHOULD signal throttling with HTTP 429 so callers back off.
  • SHOULD queue requests gracefully when traffic exceeds the budget-derived replica ceiling instead of scaling beyond budget.
  • SHOULD enforce quotas per consumer, API key or IP address per minute/hour/day to prevent abuse and implement usage tiers.
  • SHOULD check client rate limits at the gateway to prevent abuse before routing to agent services.
  • SHOULD enable rate limiting on inference endpoints.
  • SHOULD be enforced to contain unexpectedly high costs and budget overruns (Ref8.05).

Quantitative guidance

As stated by the sources; verify before use.

  • Example token bucket permits bursts of 10 operations with a sustained limit of 60 per minute (Ch9.2).
