Fallback Chain Policy

Data artifactModel ServingModelsarc:FallbackChainPolicy

A priority-ordered list of alternative resources (primary provider, secondary provider on different infrastructure, cached results) that a router attempts in sequence when the preferred resource fails.

Responsibility. Defines the ordered fallback targets for a degraded resource.

Also known as: Fallback hierarchy, Provider priority list, Fallback tool chain, AI gateway fallback policy

Design guidance

  • SHOULD place a cached-result fallback last so that total failure is avoided even when all live providers fail.
  • SHOULD NOT place alternatives that share a failure domain (e.g., the same cloud availability zone) as the only fallback.
  • SHOULD list alternative tools (e.g., a secondary flight-search API with less complete data but higher availability) invoked when the primary tool fails after retries.
  • SHOULD ensure fallbacks actually solve the problem rather than mask failures.
