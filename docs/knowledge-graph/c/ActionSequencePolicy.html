Action Sequence Policy

Data artifactSafety & SecuritySafety, Security & Governancearc:ActionSequencePolicy

A declarative set of prerequisite, ordering and prohibited-action rules stating which actions must precede others and which tools may never be invoked.

Responsibility. Encodes mandatory action prerequisites and ordering constraints.

Also known as: Hard Prerequisite Rules, Business Logic Constraints, Tool dependency declarations, Tool preconditions and postconditions, Workflow constraints

Design guidance

  • MUST enforce safety-critical sequences at system level (tool refuses without prerequisite evidence) rather than relying on agent judgment.
  • SHOULD declare dependency relationships such as 'Tool B requires Tool A to execute first' and preconditions such as 'execute only when condition X holds'.
  • SHOULD declare postconditions verifying a step's success (e.g., payment confirmed) before downstream steps or resource release proceed.

Quantitative guidance

As stated by the sources; verify before use.

  • Hard prerequisites, pre-action validation and post-hoc audit cut healthcare sequence violations 12%->0.3% over six months (Ch3.8).
