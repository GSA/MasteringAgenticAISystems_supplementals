Staged Rollout Policy

Data artifactInfrastructureInfrastructurearc:StagedRolloutPolicy

A declarative rollout specification of strategy (staged or rolling), stage percentage, validation period, rollout velocity and automatic-rollback threshold.

Responsibility. Parameterises how quickly and safely an update propagates.

Also known as: Rollout strategy, Update type strategy

Relationships

configures structural

  • Canary Rollout Controller Ref8.08
  • Edge Update Orchestrator Ch4.6
  • Rollout Manager abstract Ref10.05

Design guidance

  • Critical security patches MAY use immediate deployment after staging smoke tests with rollback ready; feature updates SHOULD use staged canary rollout; dependency updates SHOULD be tested in isolation first (Ref8.08).
  • SHOULD schedule updates in low-traffic periods and avoid Friday/holiday deployments (Ref8.08).

Quantitative guidance

As stated by the sources; verify before use.

  • Pilot example: 20% of 25 pilot stores first, 60-minute validation (Ch4.6).
  • After full rollout, monitor for 2 hours (Ref8.09).
