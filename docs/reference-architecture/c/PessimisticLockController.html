Pessimistic Lock Controller

Software componentOrchestrationOrchestration & Toolsarc:PessimisticLockController

A state concurrency controller in which instances acquire exclusive locks on workflow state before modifying it.

Responsibility. Grants exclusive access to workflow state before modification.

Also known as: Pessimistic locking

Variant of State Concurrency Controller abstract

When to choose. Choose when instances must hold exclusive access before modifying state.

Relationships

alternative to variability

  • CRDT State Merger Ch1.6
  • Optimistic Lock Controller Ch1.6 Ch8.2A

Design guidance

  • SHOULD NOT hold locks across agent computation, since this serialises agents and removes multi-agent parallelism.

Quantitative guidance

As stated by the sources; verify before use.

  • Lock contention: state reads of 80-150 ms with 3-7 agents waiting (Ch8.2A).
