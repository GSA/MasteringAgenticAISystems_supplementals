Session Affinity Load Balancer

Software componentInfrastructureInfrastructurearc:SessionAffinityLoadBalancer

A load balancer that pins all requests from the same client to the same replica so conversation context cached there is reused.

Responsibility. Keeps a client's follow-up requests on the replica holding its context.

Also known as: Sticky sessions, Client-IP affinity, IP hash, Consistent routing

Variant of Load Balancer abstract

When to choose. Choose as the simplest cache-locality option for conversational agents whose follow-up messages come from the same client.

Design guidance

  • SHOULD be treated as a temporary expedient while externalizing state, then replaced by least-connections routing.
  • SHOULD NOT be used for independent requests (e.g., document processing) where affinity yields no benefit.

Quantitative guidance

As stated by the sources; verify before use.

  • Power users can drive ~30% of traffic to one replica while others sit near 10% utilization; skew worsens with small replica counts (Ch4.7).
