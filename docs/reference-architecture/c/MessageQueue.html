Message Queue

Software componentOrchestrationOrchestration & Toolsarc:MessageQueue

An event broker providing FIFO buffering between publishers and consumers so publishers continue without waiting.

Responsibility. Buffers messages FIFO between producers and consumers.

Also known as: FIFO queue, Broker-centric message queue, Intelligent broker, Asynchronous hub, Work queue

Variant of Event Broker abstract

When to choose. Choose for FIFO buffering and temporal decoupling where queues must absorb traffic spikes and ordering matters.

Design guidance

  • SHOULD redeliver unacknowledged messages to another consumer when a consumer fails mid-processing.
  • SHOULD decouple long-running agent processing from the API: acknowledge receipt immediately, enqueue the work and free the connection.
  • SHOULD leave failed events in the queue for retry and route persistently failing ones to a dead-letter queue.

Quantitative guidance

As stated by the sources; verify before use.

  • Suited to multi-agent systems processing 4,000-10,000 messages/s with strict delivery guarantees; sub-millisecond push delivery (Ch4.1).
  • Long research workflows take 30-90 s; holding synchronous connections that long exhausts connection pools (Ch4.2).
