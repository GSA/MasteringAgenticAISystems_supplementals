Design guidance

  • SHOULD log all human interventions and all tool invocations.
  • SHOULD retain structured tool invocation logs as the audit trail supporting failure investigation and compliance requirements.
  • SHOULD record inference request tracking and compliance logs and have access logs monitored.
  • SHOULD record every filtering decision with enough detail to demonstrate compliance during regulatory examinations.
  • MUST record who requested what action, supporting context, who approved or rejected, when, and any escalations.
  • SHOULD retain detailed, traceable agent logs so decisions can be audited and challenged.
  • SHOULD capture who accessed which personal data, when, from which IP address and what action was performed.
  • SHOULD capture user actions, system decisions with reasoning, change records with authorizer, monitoring threshold crossings and incident timelines.
  • SHOULD support reconstruction of past system states and decision logic for investigation and reproducibility.
  • MUST record inputs received, reasoning applied, confidence scores, information sources consulted and final outputs for regulated automated decisions.
  • SHOULD maintain audit trails separately from, and in addition to, user-facing explanations.
  • MUST record, for each proactive suggestion, the specific data accessed, the inference drawn and the action taken.
  • MUST capture data accessed, reasoning produced, exactly what approvers saw, their decisions and justifications, and complete state at each decision point.
  • MUST record, for every consequential decision, the reasoning chain, tools invoked with parameters, data sources accessed, confidence scores and the policy evaluations that permitted or constrained the action.
  • SHOULD log data access so the organization can prove protected characteristics were never accessed in a decision.
  • SHOULD be treated as a fundamental architectural requirement, not an optional enhancement; logging only final outcomes prevents accountability.
  • SHOULD log agent findings, confidence scores, human interactions and override decisions with timestamps and user identifications.
  • Audit entries SHOULD record timestamp, user, action, input, agent decision, confidence, outcome, approval and approver, retained per policy and searchable (Ref10.06).

Quantitative guidance

As stated by the sources; verify before use.

  • Production-system records retained 5-7 years; incident documentation for full lifecycle; regulatory requests indefinitely (Ref9.03).
  • Audit logs retained 90 days in the Ref9.05 example retention table.
