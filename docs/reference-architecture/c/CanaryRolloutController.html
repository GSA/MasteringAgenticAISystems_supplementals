Canary Rollout Controller

Software componentInfrastructureInfrastructurearc:CanaryRolloutController

A rollout controller that routes a small, stepwise-increasing share of production traffic to a new agent version, compares its metrics to the baseline at each step and reverts automatically on degradation.

Responsibility. Validates a new version on incrementally expanded live traffic.

Also known as: Canary deployment

Variant of Rollout Manager abstract

When to choose. Choose when a new version should be validated on real user traffic with limited exposure before full rollout.

Design guidance

  • MUST route all traffic back to the stable version automatically when any metric degrades beyond configured thresholds.

Quantitative guidance

As stated by the sources; verify before use.

  • Traffic steps 5% -> 25% -> 50% -> 100%, metrics compared every 2 minutes with ~10 minutes per step (Ch4.1).
  • Example traffic steps 5% -> 25% -> 50% -> 100% (Ch6.5).
  • Gradual fix rollout 1% -> 10% -> 50% -> 100% of traffic with monitoring at each step (Ref8.06).
  • Canary stages 5% -> 25% -> 50% -> 100% with 30-minute monitoring each; roll back if canary success rate < 95% of baseline or p95 latency > 110% of baseline (Ref8.08).
