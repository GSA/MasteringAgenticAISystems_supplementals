Dependency Cycle Validator

Software componentOrchestrationOrchestration & Toolsarc:DependencyCycleValidator

A configuration-time validator that rejects any declared inter-agent dependency that would close a cycle, using depth-first search with a recursion stack so the dependency graph remains acyclic.

Responsibility. Rejects dependency declarations that would create a cycle.

Also known as: Cycle detection, Pre-flight dependency validation

Variant of Deadlock Controller abstract

When to choose. Choose when agent dependencies can be declared at workflow-configuration time; static validation makes runtime deadlock structurally impossible and fails fast, with no scanning cost or detection latency.

Design guidance

  • SHOULD pre-declare agent dependencies and validate them once at configuration time rather than detect deadlock at runtime.
  • SHOULD use depth-first search (tracking the current path) rather than breadth-first search for cycle detection.
  • SHOULD re-validate the graph whenever agents or dependencies are added, e.g., when splitting a bottleneck agent.

Quantitative guidance

As stated by the sources; verify before use.

  • Deadlock failures fell from 35% of failures to 0% after cycle detection (Ch8.2A).
