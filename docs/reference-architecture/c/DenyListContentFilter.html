Deny-List Content Filter

Software componentSafety & SecuritySafety, Security & Governancearc:DenyListContentFilter

A content safety filter that blocks text matching any entry of a deny list of forbidden words, phrases or compiled regular expressions.

Responsibility. Blocks text containing enumerated forbidden terms or patterns.

Also known as: Keyword filter, Pattern-matching filter, Profanity filter, Regex filter

Variant of Content Safety Filter abstract

When to choose. Choose when microsecond latency, implementation simplicity and deterministic, auditable behaviour matter, e.g., as a fast first-pass check for blatant violations before more expensive ML classifiers; avoid as sole defense where context matters or adversaries use misspellings and character substitutions.

Design guidance

  • SHOULD use word-boundary patterns to avoid substring false positives (e.g., 'kill' matching 'skill').
  • SHOULD precompile patterns once at initialization and match case-insensitively.
  • SHOULD NOT be the only defense, because it is brittle against misspellings, character substitutions and Unicode lookalikes and lacks context awareness.

Quantitative guidance

As stated by the sources; verify before use.

  • Keyword and regex patterns execute in microseconds, versus milliseconds for neural classifiers (Ch9.1).
