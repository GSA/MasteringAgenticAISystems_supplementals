Layer-4 Load Balancer

Software componentInfrastructureInfrastructurearc:L4LoadBalancer

A transport-layer load balancer that forwards TCP/UDP connections to replicas using only IP/port information, without inspecting application payloads.

Responsibility. Forwards connections to replicas based solely on transport-layer information.

Also known as: Transport-layer load balancer, Cluster service load balancer, Standard cluster service load balancing, Kubernetes ClusterIP Service, kube-proxy (iptables/IPVS), ClusterIP Service

Variant of Load Balancer abstract

When to choose. Choose when all instances are identical and all requests equivalent, so raw throughput and simplicity outweigh request-aware routing.

Design guidance

  • SHOULD be used for internal pod-to-pod traffic, health checks and metrics scraping with stable internal DNS names.
  • SHOULD set session affinity to none for stateless agents so any pod can serve any request.
  • SHOULD track only ready endpoints so routing follows pod creation, failure and rolling-update termination automatically.

Quantitative guidance

As stated by the sources; verify before use.

  • Handles millions of connections per second with sub-millisecond overhead (Ch1.8).
