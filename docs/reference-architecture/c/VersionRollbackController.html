Version Rollback Controller

Software componentInfrastructureInfrastructureVariation point (abstract)arc:VersionRollbackController

An abstract release component that returns production traffic from a newly deployed agent or model version to the previous known-good version.

Responsibility. Restores the previous known-good version after a failed or degraded update.

Also known as: Rollback procedure

Variants

VariantWhen to choose
Gradual Rollback ControllerChoose for moderate quality degradation, performance issues or non-critical bugs.
Immediate Rollback ControllerChoose for critical issues: error rate > 5%, latency > 200% of baseline, system crash/unavailability or detected data corruption.

Design guidance

  • MUST have a rollback plan prepared before any deployment (Ref8.08).
  • SHOULD keep the previous version available for quick rollback after cleanup and test the rollback procedure regularly (Ref8.08).

Quantitative guidance

As stated by the sources; verify before use.

  • Previous version retained ~4 hours (14,400 s grace period) after rollout (Ref8.08).
