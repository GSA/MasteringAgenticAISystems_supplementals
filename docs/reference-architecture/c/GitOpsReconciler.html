GitOps Reconciler

Software componentInfrastructureInfrastructurearc:GitOpsReconciler

An in-cluster, pull-based controller that continuously compares declarative desired state in a version-control repository with live cluster state and applies diffs until they match.

Responsibility. Keeps cluster state converged to version-controlled desired state.

Also known as: Continuous reconciliation, GitOps continuous delivery

Design guidance

  • SHOULD treat the repository as the single source of truth and revert unauthorized manual changes.
  • SHOULD assess resource health (replicas ready, endpoints bound) after sync rather than declaring success on apply.
  • SHOULD roll back by reverting commits (not resetting history) so rollbacks are recorded and reviewable.
  • SHOULD periodically rebuild clusters from the repository to validate disaster recovery.

As stated by the sources; verify before use.
