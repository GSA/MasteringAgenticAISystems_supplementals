Evaluation Sampling Policy

Data artifactObservability & EvaluationObservability & EvaluationVariation point (abstract)arc:EvaluationSamplingPolicy

A configuration setting what fraction of production interactions are evaluated at each deployment stage and when sampling rates increase in response to anomalies.

Responsibility. Controls online evaluation coverage versus cost.

Also known as: Sampling strategy

Variants

VariantWhen to choose
Exhaustive Evaluation Sampling PolicyChoose when comprehensive per-trace ground truth justifies ~2-5% of inference cost and ~500 ms added latency per request.
Random Evaluation Sampling PolicyChoose when a representative baseline-quality estimate is needed with no production latency impact.
Strategic Evaluation Sampling PolicyChoose for production systems where evaluation should focus on problem areas; recommended default (5-10% with error oversampling).

Design guidance

  • SHOULD increase sampling rates when anomaly detection flags concerning patterns.
  • SHOULD sample 5-10% of production traces with oversampling of errors (Ref8.03).

Quantitative guidance

As stated by the sources; verify before use.

  • Monitor 100% early, then 10-20% as systems stabilize, then 1-5% for ongoing validation (Ch3.3).
  • 10% of canary and stable conversations sampled for LLM-as-judge assessment (Ch4.2).
