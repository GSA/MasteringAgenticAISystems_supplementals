Design guidance

  • MUST validate tool inputs and handle edge cases with informative errors.
  • MUST implement timeout and cancellation for long-running operations.
  • SHOULD log all tool invocations for auditability.
  • SHOULD handle malformed structured (JSON) function-calling output gracefully rather than failing the agent run.
  • MUST treat LLM function-call recommendations as untrusted input requiring full validation before execution.
  • MUST validate that the function exists and parameters match expected types and constraints before executing in a controlled environment.
  • SHOULD log user queries, model-generated tool requests, execution results, and final responses.
  • SHOULD NOT rely on temperature=0 for determinism; use input validation, schema constraints, and result verification.
  • SHOULD run layered pre-execution checks (schema validation, semantic grounding/plausibility validation, precondition checking) before any tool executes.
  • SHOULD validate tool responses after execution before downstream agents consume them.
  • SHOULD request clarification from the user rather than proceeding when validation reveals missing or ungrounded information.

Quantitative guidance

As stated by the sources; verify before use.

  • Tool overuse rate can reach 50% or higher of all tool calls (Ch1.2).
  • Strict parameter validation reduces downstream errors 30-40% with 0.2-0.5s overhead per validation failure (Ch3.4).
