Execution Timeout Policy

Data artifactOrchestrationOrchestration & Toolsarc:ExecutionTimeoutPolicy

A configuration artifact fixing the maximum wall-clock execution time an agent run may consume before it is terminated.

Responsibility. Bounds the total execution time of an agent run.

Also known as: max_execution_time, Execution time budget, Serverless function timeout

Relationships

constrains control

  • Agent Controller abstract Ch2.8
  • Event-Triggered Agent Ch4.2
  • Worker Agent abstract Ch8.2A

Design guidance

  • MUST terminate agent runs that exceed the configured execution time.
  • SHOULD set function timeouts long enough for LLM calls (at least 5 minutes for complex agent workflows) while still bounding runaway executions.

Quantitative guidance

As stated by the sources; verify before use.

  • Default 3 s timeouts are insufficient for LLM calls taking 5-15 s (Ch4.2).
  • Worked example: 10 s for the recommendation generator, 5 s for other functions (Ch4.2).
  • 45 s workflow timeout set the pre-fix mean time to detect coordination failures (Ch8.2A).
