Conversation State Store

Data storeMemoryCognition & MemoryVariation point (abstract)arc:ConversationStateStore

A store holding per-session conversation history and agent state machine state used to continue a user's conversation across turns.

Responsibility. Holds per-session conversation state between turns of a conversation.

Also known as: Conversation history, Session persistence, Session state store, State store, Conversation Session Store, Conversation buffer memory, Per-agent message history, Kernel context, Customer preference state, Session cache, Short-term memory cache, Multi-turn specialty context cache, Unified multimodal conversation state, Short-term context

Variants

VariantWhen to choose
External Session State StoreChoose for large-scale deployments (100+ instances), frequent autoscaling that would churn sessions, or when no session may be lost on instance failure.
Instance-Local Session StateChoose when latency requirements are extreme (sub-100 ms), scale is modest (tens of instances), and session recreation after instance failure is acceptable.

Design guidance

  • SHOULD be chosen based on latency requirements, replica count, autoscaling churn and tolerance for session loss.
  • MUST scope memory to individual conversations to prevent cross-session context bleed.
  • SHOULD hold current conversation and session-specific context in a high-speed cache to avoid rebuilding context on each request.
  • MUST store multi-turn conversation history externally keyed by conversation ID; each stateless invocation retrieves history, appends the turn and stores the response.

Quantitative guidance

As stated by the sources; verify before use.

  • Clinical system cached specialty-specific context from login, avoiding context rebuilding for each note during a shift (Ch3.10).
