Multi-Hop Retrieval Controller

Software componentKnowledge & DataKnowledge & Dataarc:MultiHopRetrievalController

A retrieval control component that answers a question requiring evidence from several documents by iterating hops: resolving each sub-question, retrieving evidence, carrying intermediate answers forward, and handing results to synthesis.

Responsibility. Sequences retrieval hops and maintains intermediate reasoning state across them.

Also known as: Multi-hop QA agent, Iterative retrieval loop

Design guidance

  • SHOULD maintain reasoning state across hops so earlier findings inform later retrieval.
  • SHOULD formulate next-hop retrieval queries from intermediate results, since second-hop retrieval errors cascade.
  • SHOULD detect insufficient information and decline rather than hallucinate a confident answer.
  • MAY fall back to web navigation when required information is absent from retrieved documents.

Quantitative guidance

As stated by the sources; verify before use.

  • Three-hop tasks show 30-50% lower success than equivalent two-hop tasks; four-hop drops further (Ch3.3).
  • Reported error propagation rate 28% on minor tasks and 72% on major tasks (Ch3.3).
